[BUG] [alpha] useLinkedEditing getTagAtPosition has end-column off-by-one

Summary: Tag end column is computed as start + length, which includes one character past the tag name; hit test includes closing bracket column.

Source references:
- cortex-ide/src/components/editor/features/useLinkedEditing.ts:48
- cortex-ide/src/components/editor/features/useLinkedEditing.ts:50
- cortex-ide/src/components/editor/features/useLinkedEditing.ts:60

Deterministic proof:
Input line: '<div>'
Computed tagNameStart=2, tagNameEnd=5
Actual tag name columns should be 2..4 for 'div'.
Current check uses column <= tagNameEnd, so column 5 ('>') is included in tag hit range.
This is an off-by-one end-column inclusion.

Expected:
Tag name 'div' should occupy columns 2..4 only.

Actual:
Computed end column includes column 5, causing false-positive tag hit.
