[BUG] [alpha] RenameWidget applies rename edits twice for current file

Summary: Rename applies workspace edits via backend for all files and then applies current file edits again with model.pushEditOperations.

Source references:
- cortex-ide/src/components/editor/RenameWidget.tsx:509
- cortex-ide/src/components/editor/RenameWidget.tsx:532
- cortex-ide/src/components/editor/RenameWidget.tsx:551
- cortex-ide/src/components/editor/RenameWidget.tsx:563

Deterministic proof:
Control flow in handleSubmit:
1) For every file in workspaceEdit.changes, invoke('apply_workspace_edit', ...).
2) Then, if current editor model URI exists in workspaceEdit.changes,
   call model.pushEditOperations(...) with the same edits.

When current file is part of workspaceEdit.changes, the same logical rename edits
are applied once via backend path and once via model path.

Expected:
Each text edit should be applied exactly once per affected file.

Actual:
Current file receives both backend and model edit application paths.
